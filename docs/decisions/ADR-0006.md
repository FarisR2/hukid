# ADR-0006 — Lectura autorizada de operador y sesión

- Estado: adoptado para laboratorio AUTH-T05; no aprueba producción.
- Fecha: 2026-11-04.
- Alcance: consola HukID; complementa [ADR-0005](ADR-0005.md).

## Decisión

1. Implementar las tres lecturas del contrato mediante verificador operator compartido, middleware Bearer y servicio tenancy; mantener Management independiente de cookies.
2. Resolver roles y membership desde PostgreSQL en cada petición tenant-scoped, sin usar capacidades persistidas como autoridad. Reutilizar grants/RLS existentes y la matriz de capacidades embebida, sin nuevas migraciones.
3. Adelantar de AUTH-T06 únicamente lectura/descifrado de la generación inicial para habilitar /console/api/me. Conservar allí actualización de actividad, renovación, rotación, logout y concurrencia. Un token vencido exige nueva autenticación mientras refresh no exista.
4. Mantener selección inicial null; el comando de tenant sigue pendiente con CSRF/Origin. No añadir autoridad issuer sin el dominio/asignaciones correspondientes.
5. Exigir pools y credenciales runtime separados de sesión, descubrimiento y tenant al habilitar autenticación. Rechazar herencia combinada de esos roles. Sin configuración se conserva liveness solamente.

## Consecuencias

Se habilita lectura privada comprobable antes de completar el ciclo de sesión; no se declara consola operativa ni gate A4. Cambia la configuración manual de laboratorio: se necesitan dos DSN adicionales para roles ya existentes. No cambian schemas HTTP, audiencias, clases, wallet ni Events. Las lecturas y sus límites se describen en [contexto AUTH-T05](../03-design/console-operator-context.md); las pruebas usan únicamente recursos sintéticos descartables.
