# ADR-0009 — Navegación y estados de autenticación en consola

- Estado: adoptado para laboratorio AUTH-T08; no aprueba producción.
- Fecha: 2026-11-05.
- Alcance: React, BFF y proxy local; complementa [ADR-0008](ADR-0008.md).

## Contexto

El contrato de step-up exigía JSON y una cabecera CSRF y devolvía 303 hacia el IdP. Un formulario HTML no puede enviar ese formato/cabecera; seguir la redirección con fetch no equivale a navegar la ventana al IdP. La consola necesita manejar fallos antes de navegar sin exponer tokens.

## Decisión

1. Login y step-up aceptan negociación explícita `Accept: application/json`: devuelven 200 con `authorizationUrl` construida por el servidor. Conservan transacción, cookies HttpOnly, validaciones, rate limits y no-store. Las otras solicitudes conservan 303. No se añade un endpoint ni autoridad desde el navegador. El [OpenAPI](../../src/platform/contracts/console-auth.openapi.json) registra ambas respuestas.
2. React llama al BFF con credenciales same-origin y no-store y navega la ventana sólo después de una respuesta válida. No persiste identidad, tenant, CSRF ni tokens en storage. El CSRF vive exclusivamente en memoria. Los comandos conservan Origin exacto y JSON estricto; refresh/logout conservan cuerpo vacío.
3. El callback sigue siendo del servidor. Errores de navegación con Accept HTML reciben una página fija en español, manteniendo el estado HTTP y las cabeceras privadas. Sólo ofrece volver a `/`; no refleja parámetros, descripciones del IdP ni correlaciones en HTML. Los consumidores sin Accept HTML conservan Problem Details. No hay reintentos ni redirecciones automáticas ante errores.
4. La consola ofrece entrada, acceso pendiente, selección explícita incluso con un único tenant, contexto confirmado, renovación, step-up y logout. Los módulos de miembros y dashboard conservan sus propias features. La UI se protege mediante `/me` vigente, sin convertir el guard visual en autorización de servidor.
5. Cada operación retira la identidad visible y aborta lecturas anteriores. Una generación local impide aplicar respuestas obsoletas. Ocultar/restaurar la página y navegar en el historial retira el contexto; la restauración vuelve a consultar `/me`. BroadcastChannel avisa a otras pestañas sin compartir datos de identidad ni secretos. Un cambio de tenant desmonta el contexto anterior antes de cargar el nuevo.
6. No se mantiene la sesión viva con polling. Renovar es una acción explícita y se vuelve a leer `/me` después de cada rotación. Sin CSRF recuperable en memoria, una sesión cuyo access token ya venció requiere un nuevo login; no se relajan los controles para recuperarla. Logout sólo se presenta como exitoso tras confirmación del BFF.
7. Vite actúa como proxy local para `/console/`, preservando Origin. `HUKID_CONSOLE_API_TARGET` acepta sólo un origen HTTP IPv4 loopback sin credenciales/ruta. El API permite que el origen de la política difiera del listener únicamente si `HUKID_CONSOLE_PROXY_ORIGIN` coincide exactamente con él; ambos siguen restringidos por la política test. No se confía en cabeceras forwarded ni se habilita producción/CORS.

## Consecuencias y límites

El cambio es aditivo y conserva clientes 303. La URL de autorización contiene parámetros transitorios OIDC y no tokens emitidos; no se guarda en DOM/storage/logs. Un timeout de comando no se reintenta automáticamente: una rotación puede haber ocurrido aunque su respuesta se pierda. Revalidar o iniciar sesión permite recuperarse.

La [referencia de consola](../03-design/console-auth-interface.md) mantiene ejecución y verificación. MFA continúa sintética; AUTH-T09 conserva auditoría/redacción integrada y AUTH-T10 operación/gate final. Events y wallet no cambian.
