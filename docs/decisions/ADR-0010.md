# ADR-0010 — Auditoría transaccional de autenticación y exclusión de secretos

- Estado: adoptado para laboratorio AUTH-T09; no aprueba producción.
- Fecha: 2026-11-05.
- Alcance: auditoría/outbox propios HukID, sesiones y adaptadores HTTP; complementa [ADR-0004](ADR-0004.md) y [ADR-0009](ADR-0009.md).

## Contexto

La foundation tenía registros mínimos audit/outbox, con tenant obligatorio, sin grants runtime. Login y las denegaciones pueden ocurrir antes de seleccionar tenant o verificar actor. Asignarles un tenant ficticio o copiar claims del request introduciría datos sin autoridad. Los cambios de sesión necesitan evidencia consistente con su commit.

## Decisión

1. Ampliar las tablas existentes mediante migración forward-only 0006. Tenant puede ser null únicamente para acciones auth enumeradas. Una FK de event_id y otra de scope generado/event_id impiden referencias huérfanas o mezcla de contexto incluso con null.
2. Escribir cambio, evento y outbox en la misma transacción. Un fallo de auditoría impide confirmar la mutación. Mantener consumo OIDC previo, locks/CAS y llamadas IdP fuera de DB.
3. Conceder INSERT por columnas y vocabulario cerrado únicamente a session runtime bajo RLS forzada. Sin grants de lectura/alteración/publicación; sin nuevo rol runtime ni credenciales.
4. Generar correlación por petición en servidor y compartirla con cabecera, Problem Details y persistencia. Ignorar correlaciones recibidas; registrar denegaciones sin inferir actor/tenant de datos no verificados.
5. Registrar denegaciones HTTP en transacción independiente y acotada, incluso ante cancelación del cliente. Si falla DB, conservar el rechazo y emitir alerta fija sin error externo. No prometer persistencia de denegaciones durante indisponibilidad o caída del proceso.
6. Usar eventos sin payload/JSON/claims ni secretos. Telemetría de rechazo sólo con correlación y status; diagnósticos net/http con texto fijo para evitar fuga por panic.

## Consecuencias y límites

La [referencia de auditoría](../03-design/console-auth-audit.md) mantiene vocabulario, diccionario, garantías y verificación. Logout requiere confirmar invalidación y auditoría locales; una caída de DB no permite afirmar cierre, aunque un fallo del IdP sigue sin impedir el logout local confirmado.

No cambia ninguna operación OpenAPI, autoridad de tenants, clase/audience de tokens ni recuperación de cuenta. La evidencia se limita a laboratorio y conserva las limitaciones de AUTH-T08. Retención, publicación/visor de eventos, alertas operativas, rollout/reversión y gate A4 permanecen pendientes; el acceso runtime append-only no equivale a almacenamiento WORM ni a auditoría institucional completa.
