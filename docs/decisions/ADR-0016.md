# ADR-0016 — PATCH de membresías bajo lock tenant y ETag

- Estado: adoptada para laboratorio USR-T06.
- Fecha: 2026-11-06.
- Ámbito: FEAT-002, autorización y persistencia propia de HukID.

## Contexto

El [contrato vigente](../03-design/console-members-contract.md) exige editar grants/lifecycle con If-Match, replay reautorizado y protección del último administrador. USR-T02 preparó persistencia/archivo y USR-T05 necesita ese archivo para reingreso. Todavía no existe una fuente confiable de propiedad de issuers.

## Decisión

Conectar los dos PATCH existentes a un servicio común y al store members con RLS. Compartir el advisory try-lock tenant de invitaciones/aceptación; comprobar autorización/MFA antes y después del lock. Resolver replay autorizado antes de If-Match, ligado a target, patch canónico y revisión. Para escritura nueva, usar snapshot y conteo de admins bajo ese lock y el guard puro existente.

Cambiar estado/grants, incrementar revisión y guardar idempotencia, evento y outbox en una transacción. Archivar al revocar, sin cambiar lifecycle ni identidad. Reingreso continúa exclusivamente por invitación posterior, preservando historia y membershipId. No añadir tablas, migraciones ni permisos. Fail closed con 503 para reemplazo issuer no vacío hasta tener ownership confiable. El detalle único de comportamiento está en la [referencia USR-T06](../03-design/console-members-lifecycle.md).

## Consecuencias y límites

Las doce operaciones Management/BFF de miembros están conectadas para laboratorio. Una key reintentada no duplica efectos, pero requiere autoridad vigente; una auto-reducción puede impedir ese replay. El try-lock puede devolver 409 por otra operación del tenant; el cliente debe reintentar sin asumir éxito. El fallo de evidencia conserva el estado anterior completo.

USR-T07 conserva invalidación completa de contexto, USR-T08 UI y USR-T09 gate. No hay fuente issuer, factores/proveedor/email productivos, carga/restore ni habilitación productiva. El perfil VC sigue draft y el roadmap HK no cambia.

## Validación

Pruebas Go/PostgreSQL/HTTP y checks del incremento se registran en [tareas FEAT-002](../features/FEAT-002-user-management/tasks.md). No se atribuye evidencia visual a estos endpoints sin UI.
