# ADR-0017 — Revalidación viva y reconciliación de sesión por tenant

- Estado: adoptada para laboratorio USR-T07.
- Fecha: 2026-11-06.
- Ámbito: FEAT-001/002, autorización y sesiones propias de HukID.

## Contexto

USR-T06 confirma cambios de roles/estado y revisión con audit/outbox. AUTH ya revalida membresías en cada API, pero una selección retirada producía 404 en /me y permanecía almacenada. Las revisiones de sesión no se reconciliaban y la proyección AUTH de issuerIds seguía vacía pese al almacenamiento USR-T02. AC08 requiere aplicar los cambios preservando accesos independientes de la identidad.

## Decisión

Revalidar el tenant seleccionado en cada lectura de sesión mediante un puerto hacia tenancy. Actualizar la revisión observada o limpiar la selección si se retiró el acceso, sin invalidar identidad/familias globales. Proteger la escritura con locks family→generation y comparación del contexto observado. Mantener las comprobaciones vivas de cada API y de las mutaciones/replays; ninguna revisión almacenada sustituye autorización.

Ampliar con migración 0010 sólo la lectura tenant-runtime de scopes propios, mediante RLS por actor/membresía/tenant activos. Proyectarlos junto con roles/revisión en un único snapshot. Conservar el bloqueo de asignaciones sin ownership confiable. El detalle único de HTTP, concurrencia y errores vive en la [referencia USR-T07](../03-design/console-authorization-revalidation.md).

## Consecuencias y límites

/me puede responder 200 con selección/contexto null después de una suspensión/revocación; la interfaz AUTH existente vuelve a acceso pendiente/selector. No selecciona silenciosamente otro tenant ni amplía expiraciones. API del tenant retirado sigue denegada. Los cambios entre tenants no necesitan logout global ni comunicación con el IdP.

La reconciliación derivada es diferida hasta la siguiente lectura y no es atómica con la mutación de negocio entre credenciales separadas. Las API revalidan autoridad independientemente y no dependen de esa escritura para retirar acceso. Lecturas ya autorizadas antes de commit no se cancelan. No se añade evento de negocio por sincronizar esa selección derivada; la mutación original ya conserva audit/outbox atómicos.

La migración es expand, sin tablas/variables nuevas. USR-T08 conserva pantallas de miembros y USR-T09 gate/operación. Sin producción ni nuevo dominio issuer; el perfil VC continúa draft y el roadmap HK conserva su orden.

## Validación

Pruebas unitarias, PostgreSQL/HTTP y Chromium; comandos y resultados en [tareas FEAT-002](../features/FEAT-002-user-management/tasks.md). El test de rotación step-up inyecta el resultado OIDC en el store; la regresión HTTP existente cubre el intercambio real sintético.
