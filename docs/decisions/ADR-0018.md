# ADR-0018 — UI administrativa y custodia de aceptación

- Estado: aceptado para laboratorio USR-T08, 2026-11-06.
- Alcance: [FEAT-002](../features/FEAT-002-user-management/spec.md); [referencia de interfaz](../03-design/console-members-interface.md).

## Contexto

Las doce operaciones Management/BFF ya están implementadas. USR-T08 debe ofrecer gestión accesible y canje sin membership, conservar una edición ante 412 y evitar transportar el código de invitación por navegación OIDC, historial o storage. Las capacidades y revisiones del navegador no son autoridad.

## Decisión

Reutilizar AUTH, su cliente y carril Web Locks, tokens visuales y /me. Añadir componentes de miembros/invitaciones y aceptación dentro de src/console, sin nuevas APIs, paquetes ni migraciones. La referencia enlazada mantiene el detalle de comportamiento para evitar duplicarlo aquí.

Concretar el fragmento de invitación con custodia sólo en memoria y retirada previa al render. Si hace falta navegar para autenticar, descartar el intento y pedir reabrirlo después. No guardar borradores ni secretos en web storage. Reintentar exactamente una escritura incierta con la misma key; una revisión/payload nueva usa otra.

Ante 412 conservar la propuesta, bloquear reenvío hasta cargar el estado vigente y exigir revisión/confirmación explícitas. Diálogo nativo con objetivo, razón y consecuencia para modificar o revocar acceso. El backend mantiene autorización viva, MFA, ETag, idempotencia y protección del último administrador. La UI no habilita ownership issuer ausente.

## Consecuencias

Se conserva la identidad y el modelo tenant existentes. Salir, reautenticar u ocultar la página puede descartar el borrador; la UI lo explica para MFA. Recargar no recupera un intento de aceptación consumido. Los errores de destinatario/expiración siguen genéricos y no revelan PII. La entrega de laboratorio y la segunda identidad OIDC son sintéticas. USR-T09 y los bloqueos productivos continúan abiertos.
