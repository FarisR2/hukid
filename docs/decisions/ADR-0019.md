# ADR-0019 — Baseline de lectura del dashboard

- Estado: aceptado para contrato de laboratorio DASH-T01, 2026-11-06.
- Alcance: [FEAT-003](../features/FEAT-003-dashboard/spec.md), DASH-T01 únicamente.

## Contexto

AUTH y USR entregan contexto vivo, miembros y auditoría mínima. No existen los dominios issuer/definition/issuance/status ni atribución issuer en auditoría. Las rutas overview/activity eran propuestas sin schemas ni límites. Se necesita un contrato verificable antes de conectarlas.

## Decisión

Materializar OpenAPI independiente con cuatro GET Management/BFF, schemas estrictos, catálogo de métricas, perfil test cerrado, fixtures y reglas puras Go de filtros. La [referencia contractual](../03-design/console-dashboard-contract.md) mantiene semántica, errores, permisos, cursor y límites como única fuente narrativa de detalle.

Reservar status:read sin concederlo en la matriz existente. Fuentes no autorizadas no revelan disponibilidad ni asOf. Las ausentes autorizadas devuelven unavailable, nunca cero. El feed excluye hechos globales y sin atribución issuer cuando el alcance la exige. No añadir grants SQL, tablas, endpoints, dependencias ni datos simulados operativos en este incremento.

Concretar solicitudes como total createdRequests; diferir el desglose por estados y el watermark de publicación status hasta tener contratos de sus dominios. La spec y la referencia registran la diferencia frente a las métricas inicialmente propuestas, sin inventar enums o evidencia de publicación.

## Consecuencias

El contrato permite preparar casos cliente/proveedor sin fingir módulos disponibles. La validación JSON cubre forma; Go cubre relaciones temporales y límites. La autorización viva, consultas, autenticidad de cursor y snapshot requieren DASH-T02/03 y pruebas de integración posteriores. El futuro ownership y las capacidades de dominio requieren decisiones propias; no se infieren de UUIDs ni de tenant_admin. El perfil HukID continúa draft y producción conserva sus bloqueos.
