# ADR-0021 — Perímetro HTTP y cursor del dashboard

- Estado: aceptado para laboratorio DASH-T03.
- Fecha: 2026-11-06.
- Owner: Team 5.
- Relación: [ADR-0019](ADR-0019.md), [ADR-0020](ADR-0020.md), [FEAT-003](../features/FEAT-003-dashboard/spec.md).

## Contexto

DASH-T02 aporta lectura autorizada pero no rutas ni cursor público. La actividad necesita paginación acotada que no permita reutilizar una posición con otra autorización o renovar su TTL. AUTH y USR conservan sus representaciones históricas de errores; el contrato nuevo dashboard exige códigos propios, correlación UUID y 422 invalid_cursor.

## Decisión

Conectar cuatro GET Management/BFF con credencial SQL dashboard separada y configuración opcional completa de laboratorio. Reutilizar Bearer/sesión, contexto vivo y matriz de capacidades, sin nuevos grants. El adaptador dashboard aplica su representación contractual sin alterar errores AUTH/USR. BFF resuelve tenant inaccesible antes de comparar selección, manteniendo 404 y 403 respectivamente.

Autenticar el cursor AES-256-GCM dentro del callback del snapshot, después de reautorizar y antes de leer filas. Ligar mediante digest SHA-256 la operación, actor, revisión, tenant, roles/scopes ordenados y filtros normalizados. Mantener posición, asOf y deadline autenticados, TTL fijo de 900 segundos y clave exclusiva. No compartir tokens ni AAD con el directorio de miembros.

La [referencia HTTP](../03-design/console-dashboard-http.md) mantiene configuración, errores, fuentes, retirada y pruebas. Se valida el JSON serializado del API real contra el schema, además de las pruebas puras y SQL.

## Consecuencias

Cambiar permisos, contexto o clave invalida continuación; se reinicia la paginación. Una lectura conserva el snapshot de autorización; la siguiente observa revisiones nuevas. Rotación no tiene convivencia de claves y el feed no es una exportación transaccional entre páginas. No se amplían grants ni se inventa ownership/atribución issuer.

Las fuentes futuras permanecen protegidas. El único conteo conectado no permite demostrar un fallo de una segunda fuente en un 200 parcial real; los fixtures conservan esa cobertura contractual y DASH-T05 la aplicará a cada dominio conectado. DASH-T04 mantiene UI; DASH-T06–T08 gate ampliado/operación. No acredita producción, carga, interoperabilidad VC o CI remoto.
