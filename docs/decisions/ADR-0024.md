# ADR-0024 — Infraestructura incremental shadcn/Base UI de la consola

- Estado: aceptada por el owner para las fases 1 y 2; adopción en AUTH registrada en la [actualización 2026-11-08](#actualización-2026-11-08--adopción-en-auth); resto de pantallas pendiente.
- Fecha: 2026-11-08.
- Alcance: infraestructura frontend de `src/console`, lockfile raíz y documentación/pruebas asociadas.

## Contexto

La consola React/TypeScript/Vite usa npm workspaces, CSS propio y elementos nativos. AUTH/USR/DASH conservan sus flujos y clientes. El owner autoriza integrar Tailwind v4 y shadcn con Base UI, sin sustituir componentes, modificar contratos, backend o persistencia ni crear commits o publicar.

Los selectores globales de controles, formularios, títulos y párrafos pueden contaminar primitivas nuevas. CSS sin capa tiene prioridad sobre utilidades dentro de capas. Preflight cambia márgenes, encabezados, listas y controles nativos; activarlo ahora ampliaría la migración. `--muted` identifica texto secundario en HukID y una superficie en shadcn. El preset también cambia colores, radio y fuente aprobados.

## Decisión

1. Integrar `@tailwindcss/vite` v4 en el Vite existente. Conservar proxy, cabeceras y workspaces; alias `@/*` resuelto por TypeScript y Vite dentro de la consola.
2. Inicializar mediante CLI oficial shadcn 4.23.0, `init --base base --preset nova --no-monorepo --no-reinstall --yes`. La CLI actual recibe `nova`; genera `style: base-nova`. `info --json` confirma base `base`, v4, SPA/TSX y cero componentes.
3. Mantener `components.json`, utilidad `cn` generada por CLI y carpeta `components/ui` vacía. Base UI queda disponible como biblioteca seleccionada; ninguna primitiva entra en las pantallas de este incremento. No introducir tablas, iconos, fuentes remotas ni bibliotecas de formularios.
4. Importar explícitamente `tailwindcss/theme.css` y `tailwindcss/utilities.css`, omitiendo Preflight. Capas en orden `theme, base, legacy, components, utilities`; las tres hojas existentes comparten `legacy` y mantienen su orden de importación. Los selectores heredados por elemento y `aria-pressed` excluyen marcadores `data-slot` mediante `:where`, sin aumentar especificidad. Las composiciones existentes siguen en sus módulos.
5. Conservar valores hex, fuente Segoe UI/system-ui, radio de .5rem, control de 3rem, geometría y breakpoint. Mapear colores semánticos a la paleta existente en el mismo CSS. Renombrar únicamente el token de texto `--muted` a `--muted-foreground`; `--muted` pasa a superficie de fondo. Conservar la clase `.muted` y el texto de las pruebas de contraste con el nuevo nombre de token.
6. Tema determinado por `prefers-color-scheme`, también para la variante Tailwind `dark`. No añadir provider, selector persistente ni clase `.dark` como segunda autoridad. Los colores semánticos se heredan desde la raíz, incluidos futuros portales.
7. Revisar y descartar la paleta neutral, Geist, nuevos radios y reglas globales generados por init. Retirar `shadcn`, `tw-animate-css`, Geist, iconos y CVA instalados automáticamente; no hay componentes que los necesiten en esta fase. Mantener `cn` 0.5.2 generado por la CLI actual, en lugar de introducir además clsx/tailwind-merge.

## Consecuencias y verificación

Preflight queda deliberadamente pendiente: los futuros componentes deberán verificar sus estilos calculados sin ese reset y, cuando sea necesario, incorporar bases locales en vez de modificar todo el documento. No importar indiscriminadamente el CSS global del preset ni activar Preflight en la fase 3.

La autodetección `project.tailwindCss` de la CLI devuelve null con imports separados; `config.resolvedPaths.tailwindCss` sí apunta a `src/styles.css`, `tailwindVersion` es v4 y `add --dry-run/--view` resuelve el archivo bajo `src/components/ui`. No se falsifica el import para el detector. Revisar este detalle al actualizar CLI.

La consulta MCP genérica devuelve Radix sin contexto de este workspace. La autoridad para la variante instalada es `components.json` y `info`, contrastada con la vista previa CLI: Button importa `@base-ui/react/button`, sin conservar ese archivo. La vista previa usa CVA aunque el resumen de dependencias solo enumera cn: verificar imports y peer dependencies al añadir cada componente futuro.

No cambian JS/TSX de flujos, clientes HTTP, navegación, APIs ni bases. El lockfile incorpora dependencias de la infraestructura; no cambia versiones de paquetes previamente existentes. La baseline y resultados posteriores se registran en la [evidencia del incremento](../frontend/audits/2026-11-08-shadcn-infraestructura.md).

## Actualización 2026-11-08 — adopción en AUTH

La decisión original no cambia. Esta sección reconcilia el texto con el estado real del código tras el incremento de [acceso shadcn](../frontend/audits/2026-11-08-login-shadcn.md); no se reescriben los puntos anteriores, que describen las fases 1 y 2.

- **Alcance de la adopción.** La fase 3 incorpora por CLI `Button`, `Field`/`FieldGroup`/`FieldLabel`/`FieldError`, `NativeSelect`, y sus dependencias `Label` y `Separator`, únicamente en `src/console/src/authentication/AuthConsole.tsx`. USR y DASH conservan sus controles nativos. Esto sustituye lo dicho en el punto 3 (carpeta `components/ui` vacía) y en el primer párrafo de Consecuencias (ninguna primitiva en pantallas) a partir de esta fecha.
- **Dependencias.** El punto 7 preveía retirar CVA, iconos y `shadcn`. Estado verificado: `class-variance-authority` 0.7.1 **se conserva** porque `button.tsx` y `field.tsx` lo importan; `cn` 0.5.2 se mantiene en `lib/utils.ts`; `shadcn`, `tw-animate-css` y Geist siguen fuera. `lucide-react` 1.70.0 **se conserva** porque `native-select.tsx` importa `ChevronDownIcon`; es el único uso. Con ello, la regla "no introducir iconos" del punto 3 queda limitada a pantallas: el icono entra solo como parte del componente generado.
- **TSX de flujos.** El párrafo "No cambian JS/TSX de flujos" aplicaba a las fases 1 y 2. `AuthConsole.tsx` ahora usa las primitivas y, desde esta fecha, sitúa Cerrar sesión en el encabezado y presentaba el estado anónimo como tarjeta centrada, eliminada después por [ADR-0025](ADR-0025.md) ([AUTH interfaz](../03-design/console-auth-interface.md#encabezado-de-sesión-y-acceso-centrado--2026-11-08)). Callbacks, clientes HTTP, contratos y la delegación al IdP no cambian.
- **Pendiente de aprobación.** El ajuste visual del encabezado y del acceso anónimo modifica el wireframe aprobado en el [design system](../frontend/design-system.md); requiere confirmación del owner.
