# ADR-0027: Console shell with sidebar and one view per section

- Status: accepted on 2026-11-09 (owner decision: implement the [console prototype](../03-design/console-prototype/README.md) in the console).
- Date: 2026-11-09.

## Context

The console is a single page with anchors (`#title`, `#overview`, `#members-title`). Dashboard, members and invitations compete for one scroll, invitation forms are fixed cards and member editing is inline. The [approved prototype](../03-design/console-prototype/README.md) proposes a sidebar shell with one view per section. It was marked as an undecided visual proposal until this ADR.

## Decision

1. Adopt the prototype layout: 252 px sidebar (brand, organization selector, grouped navigation, user menu), 56 px top bar with breadcrumbs, content up to 1200 px with a single `h1` per view, and mobile menu below 900 px.
2. Navigation by view with public hashes `#resumen`, `#actividad`, `#miembros` and `#invitaciones`. An item without the required capability is not shown; a direct hash shows an explanation and a link to the summary. Invitation fragments (`#invitation=`) and unknown hashes are still removed before rendering and never stored.
3. Activity becomes its own view; the summary keeps only the five latest entries. Invite person and Accept an invitation become dialogs; Edit access becomes a 480 px side panel. Confirmations stay as native dialogs. Messages stay as inline banners, never toasts.
4. Menu groups and capabilities: General (Resumen `dashboard:read`, Actividad `audit:read`), Acceso (Miembros `members:read`, Invitaciones `invitations:read`). Emisión (Emisores, Definiciones, Solicitudes, Credenciales) and Organización (Ajustes) appear as in the prototype, marked "Pronto", and open a future-section view. They have no capability, data, API or behavior and are outside the [roadmap](../05-delivery/hukid-roadmap.md).
5. The prototype theme toggle is not implemented; the console keeps following the system preference. Controls keep the [design system](../frontend/design-system.md) size (3 rem, 44 px touch targets), not the prototype's 40 px.
6. No API, contract, permission or normative text changes. Permissions come from `/console/api/me` and the backend, not from the prototype's role assumptions. Prototype data, panel and simulated logic are not copied.

## Consequences

`navigation.ts`, the dashboard and member components and the browser tests that restore sections must change. The shell needs Sidebar, Sheet, Table, Badge and Dialog components from the shadcn `base-nova` registry. Rollback is returning to the previous bundle; no data or migration is involved.

The interface specs [dashboard](../03-design/console-dashboard-interface.md) and [members](../03-design/console-members-interface.md) record the approved layout. Implementation order and validation follow the prototype README.
