## Pendiente ejecutado en este incremento: HK-025

Se eligió la opción B porque es la única que puede cerrarse con servicio y almacenamiento existentes sin depender de Vault Docker, permisos administrativos ni payload de producto. `cmd/worker` ahora acepta `deferred <tenant-id> [limit]`, con lote acotado (1–500; default 50), configuración del mismo runtime Issuance/PostgreSQL/Vault y procesamiento tenant-scoped. La selección excluye transacciones expiradas. Se conserva el comando anterior del worker de invitaciones.

El batch hace selección y fulfillment en transacciones separadas. Las transiciones finales siguen protegidas por locks y estado en `FulfillDeferredRequest`; despliegues paralelos pueden realizar trabajo de firma redundante antes de que una transacción gane. Falta definir scheduler/reintentos/concurrencia operativa y métricas; por eso HK-025 queda **parcial** hasta el gate y el despliegue probado.

Archivos nuevos/modificados para esta opción: `src/platform/cmd/worker/main.go`, `src/platform/cmd/worker/deferred.go`, `src/platform/cmd/worker/deferred_test.go`, `src/platform/internal/issuance/store.go`, `src/platform/internal/issuance/service.go`, `src/platform/internal/issuance/service_test.go`, `src/platform/internal/adapters/postgres/issuance_store.go`, `src/platform/internal/adapters/postgres/issuance_store_integration_test.go`.
