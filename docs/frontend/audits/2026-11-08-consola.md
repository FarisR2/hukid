## Hallazgos

### F-001 · Media · DOC-MISSING — falta una referencia visual consolidada

- **Dónde:** [tokens y estilos base](../../../src/console/src/styles.css), [estilos USR](../../../src/console/src/user-management/styles.css) y [estilos DASH](../../../src/console/src/dashboard/styles.css).
- **Regla:** DOC-MISSING y TOKEN-02/03/04. Las referencias de interfaz prometen reutilización de tokens, pero no fijan una escala visual completa ni variantes y layouts por estado.
- **Evidencia:** hay tokens de color, espacios y controles en `styles.css:1–9`; no se encontró design system ni wireframes consolidados. Las decisiones de tipografía y medidas están dispersas.
- **Impacto:** futuras pantallas pueden divergir y las revisiones no tienen una referencia visual única.
- **Corrección sugerida:** documentar los tokens existentes, tipografía, variantes, layouts de acceso/contexto y estados; enlazar las referencias funcionales. No adoptar una librería nueva sólo para cerrar este hallazgo.

### F-002 · Media · LAYOUT-01/02, ISO E4 — el layout de trabajo invade el acceso anónimo

- **Dónde:** `src/console/src/user-management/styles.css:10–13`, `src/console/src/authentication/AuthConsole.tsx`; captura local `2026-11-08-consola/screens/login-desktop.png`.
- **Regla:** agrupación por proximidad y uso intencional del espacio. La referencia AUTH describe una superficie de acceso y contexto lateral.
- **Evidencia:** `workspace` se aplica a todos los estados; `.workspace .access-panel` impone dos columnas y `min-height:34rem` también sin sesión. A 1440 px el texto y el botón quedan separados en columnas dentro de un panel con una gran zona inferior vacía; el contexto lateral se oculta globalmente.
- **Impacto:** la acción de acceso pierde proximidad con su explicación y el primer contacto parece menos cuidado que las vistas operativas.
- **Corrección sugerida:** aplicar el layout de trabajo sólo al contexto autenticado. Definir un acceso compacto con explicación y acción juntas; comprobar CLS al cambiar de estado para conservar la estabilidad ya conseguida.

### F-003 · Media · FLOW-03, ISO A4 — la inicialización borra las anclas de navegación

- **Dónde:** `src/console/src/main.tsx:10`, `src/console/src/user-management/client.ts:66–70`, `src/console/src/dashboard/WorkspaceNavigation.tsx:14–18`.
- **Regla:** preservar ubicación del flujo y navegación coherente. DASH documenta enlaces a secciones semánticas.
- **Evidencia:** `captureInvitation()` elimina cualquier fragmento mediante `replaceState`, aunque sea `#overview`, `#members-title` o `#title`. Una reproducción aislada ejecutando la función actual con una ventana simulada confirmó que los tres se convierten en `/`. La navegación selecciona entonces el primer enlace disponible.
- **Impacto:** recargar o abrir un enlace a una sección pierde el destino solicitado. Los enlaces dentro de una sesión ya cargada sí funcionan; la suite verifica ese caso.
- **Corrección sugerida:** distinguir fragmentos de invitación de anclas de navegación allowlisted. Mantener la retirada inmediata y el descarte seguro de códigos; restaurar el destino de sección una vez renderizado el contexto autorizado.
- **Límite:** reproducción de inicialización en JavaScript, sin un E2E específico de recarga a ancla en esta revisión.

### F-004 · Media · STATE-07, ISO C1 — la confirmación no explica la retirada de alcances issuer

- **Dónde:** `src/console/src/user-management/forms.tsx:46–51`, `:153`, `:181–185`; referencia [USR](../../03-design/console-members-interface.md).
- **Regla:** confirmar el objeto y las consecuencias del cambio. La referencia USR establece que quitar `issuer_operator` elimina sus alcances mediante un reemplazo explícito de roles.
- **Evidencia:** cambiar roles envía `issuerIds: []`; el diálogo muestra objetivo, razón y roles propuestos, pero no enumera los alcances actuales que se retirarán ni advierte esa consecuencia. La ayuda general explica que se conservan al cambiar sólo el estado, sin detallar el caso contrario.
- **Impacto:** un administrador puede confirmar la retirada de permisos de emisores sin comprender todo su efecto.
- **Corrección sugerida:** mostrar la diferencia de roles y un aviso específico cuando se retiren alcances issuer existentes. Mantener intacta la restricción actual de asignación de emisores.
- **Límite:** confirmado en código; no se ejecutó una mutación con scopes issuer existentes. La confirmación sí existe, por eso no se clasifica como bloqueo por ausencia de confirmación.

### F-005 · Media · STATE-06/A11Y-02, ISO C2 — error de código sin asociación al campo

- **Dónde:** `src/console/src/user-management/forms.tsx:195–211`.
- **Regla:** error de validación asociado al campo y recuperación identificable; USR-QR03 exige errores asociados.
- **Evidencia:** un código con longitud/formato inválidos muestra `command.error` en un `role="alert"`, pero el input no recibe `aria-invalid` y su `aria-describedby` sólo referencia `accept-help`. El mensaje tampoco tiene ID para asociarlo. El código ingresado se conserva.
- **Impacto:** el error se anuncia al aparecer, pero no queda ligado programáticamente al campo al volver a él con tecnología asistiva.
- **Corrección sugerida:** separar la validación del código del error global de red, asignar ID al error de campo, enlazarlo mediante `aria-describedby` y establecer `aria-invalid`; enfocar el código al fallar esa validación. No marcar el código inválido sólo por una caída del servicio.

### F-006 · Baja · TOKEN-01/03/04 — valores visuales fuera de tokens

- **Dónde:** `src/console/src/user-management/styles.css:39`, `src/console/src/styles.css:21–22`, `src/console/src/dashboard/styles.css:13`.
- **Regla:** colores y escala tipográfica centralizados. Las coincidencias se confirmaron leyendo su contexto.
- **Evidencia:** backdrop literal `#0009`, tamaños tipográficos y grosores definidos directamente en reglas de componentes, sin tokens semánticos correspondientes.
- **Impacto:** mantenimiento y ajuste de temas menos consistentes; no se demostró un fallo de contraste causado por esos valores.
- **Corrección sugerida:** incorporar token de backdrop y escala tipográfica a la referencia visual de F-001; evitar convertir cada píxel estructural en un token sin utilidad.

## No verificado

- Todas las pantallas en cada estado a 390 y 1280 px exactos; se usaron los tamaños del harness existente.
- Revisión manual de cada captura de la suite, tema oscuro completo, todos los contrastes computados, lector de pantalla, navegadores alternativos, dispositivo físico y zoom nativo.
- axe/Lighthouse y métricas de campo; no se ejecutó un gate integral ni la suite PostgreSQL separada para esta auditoría sin cambios de persistencia.
- Mutaciones con scopes issuer existentes, recarga a anclas en navegador y prueba específica de asociación accesible del error de código: hallazgos estáticos/reproducción aislada indicados arriba.
- CI remoto, MFA/IdP/correo reales, producción y fuentes futuras DASH-T05. La ausencia de esas fuentes no es un defecto nuevo de frontend.

## Qué conviene conservar

- Datos ausentes, cero y falta de permiso diferenciados con texto.
- Recuperación 412 sin reaplicar automáticamente, idempotencia y confirmaciones explícitas.
- Contexto y permisos revalidados; descarte de respuestas tardías y custodia del código en memoria.
- Controles amplios, etiquetas visibles, idioma uniforme y reflow sin scroll horizontal en tamaños probados.
